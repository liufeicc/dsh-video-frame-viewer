# 视频逐帧查看（DSH 插件）

在 DSH Web 界面的**左侧全局图标栏**打开一个整页查看器，用来逐帧检查本地 MP4。

## 两种打开方式

1. **左侧工具栏 → 视频逐帧查看**：整页查看面板。
2. **多工作区平铺 → 任务分派 → 「视频逐帧查看」按钮**：浮动窗口，不离开当前面板。
   窗口可拖动标题栏移动、双击最大化、右下角缩放，Esc 关闭；关闭后再打开会回到
   上次的视频与位置。

## 功能

- 打开本地 MP4（文件选择、拖拽到面板），文件不上传，只在浏览器里读取。
- 正常播放 / 暂停，0.1×–4× 变速（快捷档位 + 细调滑杆）。
- 精确逐帧：前后单帧、Shift + ←/→ 跳 10 帧、Home/End 首尾帧。
- 帧胶片：默认**每秒一张**（显示当前秒附近 9 秒）；**双击某一秒**展开该秒的全部帧，单击任意缩略帧直接查看那一帧；跳到别的秒会自动收起。
- 时间轴按帧拖动；界面显示帧号、时间戳、真实帧率与总帧数。
- **复制当前帧**：暂停时点击播放控制条右侧的复制按钮，把当前画面以**原始分辨率 PNG** 写入系统剪贴板；播放中按钮不可用。
- **多选拼图**：逐帧视图里 `Shift + 单击` 连选一段、`Ctrl/Cmd + 单击` 多选；选中多帧后点复制，按帧号顺序拼成一张大图写入剪贴板（每格标帧号，列数按视频比例自动排布）。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| 空格 | 播放 / 暂停 |
| ← / → | 上一帧 / 下一帧 |
| Shift + ← / → | 后退 / 前进 10 帧 |
| Home / End | 第一帧 / 最后一帧 |
| `[` / `]` | 降速 / 升速 0.25× |
| Esc | 由 DSH 面板/对话框处理，本插件不拦截 |

## 逐帧视图的滚动布局

- 双击某一秒进入逐帧视图后，胶片区域限制在约两行高度（`min(24vh, 220px)`），**内部独立上下滚动**。
- 整个查看面板不滚动，视频区域不会被一秒 60 帧的缩略图撑小；秒视图只有一行，不出现滚动条。
- 胶片滚动条只出现在胶片区域右侧，滚轮在胶片上滚动的是胶片，不是整个窗口。

## 长时间使用为什么不卡

- 缩略图按钮用 `React.memo` 包住：播放/翻帧时只有当前帧、选中状态变化的那一两张重渲染，其余几十张直接跳过。
- 缩略图生成每 120ms 批量刷新一次，不是每抓一张就全量重渲染。
- 播放时的界面时钟从 100ms 放宽到 250ms，减少 60 个缩略图条目的 diff 次数。
- 缓存淘汰只淘汰**不在当前视图里**的缩略图；正在看的那一屏不会被删成「生成中」。
- 秒视图和逐帧视图的条目列表分开缓存：播放时不会每帧重建一秒 60 个对象。
- 抓帧失败/空 data URL 不再写入缓存，避免出现破图。

## 大视频、长 GOP 与 B 帧

- 打开视频后先等可绘制数据（`loadeddata`）再 seek；seek 后等 `seeked` 再等一帧 rVFC。长 GOP 视频（例如关键帧间隔 4 秒）一次 seek 要解码上百帧，所以超时放宽到 5 秒。
- 超时不会把旧画面当成目标帧缓存：抓帧失败就返回 `null`，缩略图保持「生成中…」，不会把上一帧存成这一帧。
- 浏览器对 B 帧的 seek 可能停在相邻帧（常见是前一帧）。这时界面帧号会按实际画面校正（例如点 482 可能落到 481）；缩略图和主视频画面保持一致。
- 如果需要严格到每一帧都不差，下一步方案是用 WebCodecs 从关键帧连续解码，而不是依赖 `<video>.currentTime` 的 seek。

## 缩略图为什么能更快

抓一帧要「seek → 等解码器从关键帧解到目标帧 → 等画面更新 → 编码」。串行做
30 张就是 30 段解码等待。现在：

- **3 个隐藏 video 并行抓帧**：任意时刻 3 张同时在解码，其余排队；
- 缩略图只做 **192px 宽、JPEG 0.62**（胶片显示宽度约 100px，原来的 320px/0.72 是白花时间）；
- **离当前帧越近的缩略图越先生成**，双击展开后能先看到自己正在看的那一帧；
- 换视频时用 generation 标记丢弃旧任务，不会把上一段视频的帧写进新缓存。

无头 Chrome（软件解码）实测：双击展开一秒的 30 张缩略图，**约 0.44 秒**全部出现。

## 为什么能精确到帧

`<video>` 只暴露时长，不告诉浏览器有多少帧。插件按顶层 MP4 box 逐个跳过 `mdat`，
只读取 `moov` 索引区，从 `mdhd`（时间刻度）、`stts`（每帧时长）、`ctts`（B 帧呈现偏移）
算出每一帧的 PTS，于是：

- 帧号 → 时间戳是精确的；
- 前后翻帧 = seek 到相邻帧的 PTS，而不是「按 30fps 估算着跳 1/30 秒」；
- 总帧数、帧率、VFR 标记都来自文件本身。

分片 MP4（moov 里没有 stts）或解析失败时，自动退回 `requestVideoFrameCallback`
实测帧率，并在状态里标明「估算帧率」；再失败按 30fps 兜底。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `client.js` | 入口：装载代码块、注册侧边栏图标与 `main` 面板 |
| `client.mp4.js` | MP4 box 解析与帧时间轴 |
| `client.playback.js` | 时间格式化、seek 等帧、rVFC 实测帧率 |
| `client.icons.js` | SVG 图标 |
| `client.styles.js` | 样式（全部使用 `--dsw-alias-*` 主题 token） |
| `client.dicts.js` | 中英文案 |
| `client.view.js` | React 视图：播放器、控制条、帧胶片 |
| `client.window.js` | 浮动窗口外壳：拖动、缩放、最大化、Esc |
| `client.strip.js` | 帧胶片：按秒浏览、双击展开该秒全部帧、Shift/Ctrl 多选 |
| `client.sheet.js` | 抓帧池（3 路并行）与多帧拼图、剪贴板写入 |
| `client.copy.js` | 复制状态机与播放控制条右侧的复制按钮 |
